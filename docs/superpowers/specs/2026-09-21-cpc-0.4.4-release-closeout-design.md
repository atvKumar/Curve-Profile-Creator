# CPC 0.4.4 Release Closeout Design

## Purpose

Finish the Curve Profile Creator 0.4.4 transform and connectivity milestone without introducing another source of transform state. The remaining work is:

- issue #8: semantic viewport controls for component Rotation/Size and committed-profile Rotation/Uniform Scale;
- issue #6: explicit Reconnect Touching Endpoints;
- issue #7: production regression validation against CRN-4000 through CRN-4004;
- a final audit of issues #2 through #10, documentation, clean packaging, and branch handoff.

The release succeeds when every interaction path resolves through CPC's existing semantic state, production validation passes in Blender, the install archive contains no development-only files, and the 0.4.4 documentation describes the behavior that actually ships.

## Constraints and protected behavior

- Keep recipe schema 11+, transform schema 1, and `.cpcprofile` format v1.
- Preserve PARAMETRIC and STATIC preset behavior, profile normalization, packed-component restoration, committed-object identity on Recommit, and Sweep bevel-object relationships.
- Preserve lazy viewport-overlay handler creation required for Blender Extensions compliance.
- Do not introduce persistent overlay-only Rotation or Size values.
- Do not infer connectivity automatically from proximity. Reconnection occurs only when the user invokes the operator.
- Do not move geometry during reconnection.
- The current semantic G/R/S, placement wheel, numeric properties, Edit Active Profile, Recommit, save/reload, and Sweep paths remain authoritative.
- WebP thumbnail work is not part of this release and will return to the later-candidate roadmap.

## Architecture

### Shared semantic editing surface

The existing viewport editor remains the interaction shell. Its field model is generalized from length-only dimensions to semantic fields with explicit value kinds and edit behavior:

- `LENGTH`: existing Scene/Metric/Architectural parsing and formatting;
- `ANGLE`: displayed in degrees and stored in radians;
- `FACTOR`: positive unitless decimal value;
- `RESIZE_ACTION`: a transient positive multiplier applied to captured component dimensions.

The overlay owns only transient gesture state: active field, input text, pointer baseline, and cancellation snapshot. Authoritative values remain on CPC objects, packed controllers, or the committed profile placement record.

The operator identifier `cpc.viewport_dimension_edit` and the E key binding remain stable for compatibility. User-facing text changes from dimension-only wording to semantic viewport editing.

Panel buttons, viewport fields, and keyboard R/S gestures invoke the same semantic gesture backends. They do not maintain separate modifier rules or alternate scale values.

### Target classification

The overlay supports exactly two selected-object contexts:

1. A non-preview parametric CPC construction part.
2. A committed CPC profile curve that is not itself a construction part.

Changing selection, deleting the target, disabling Viewport Guides, or leaving the supported context ends the modal session safely.

## Issue #8: semantic viewport controls

### Component fields

The component HUD shows:

- the current Edit Anchor;
- editable `Rotation`;
- editable `Size`, displayed as `1.000×` when idle;
- the component's existing semantic dimensional fields.

`Rotation` reads and writes `cpc_part_rotation`. Pointer scrubbing is relative to the value captured when the field gesture begins. Exact typed input is an absolute angle in degrees. Rotation remains signed and unrestricted. Escape/right-click restores the captured value.

`Size` is an action, not a stored component property. Starting the gesture captures the same basic-part or packed-controller dimensional state used by semantic S. Scrubbing or typing applies an absolute multiplier to that fixed gesture baseline. All length-valued construction parameters scale; Bias, Fullness, flips, rotations, modes, and other dimensionless values do not. Geometry regenerates through the existing semantic resize backend, Maintain Connected behavior remains active, and every object in the resize scope finishes with Object Scale `1,1,1`.

After a Size gesture is accepted or cancelled, the idle HUD returns to `Size 1.000×`. The changed construction dimensions are the only lasting size state.

### Selected-part panel controls

The selected-part panel adds a `Size` semantic action alongside Rotation. It launches the same relative semantic resize gesture as S and the overlay Size field, so it is not a persistent Scale property. The gesture begins at `1.000×`, supports pointer scrubbing and exact typed factors, and returns to `1.000×` after acceptance or cancellation.

The panel also exposes the semantic Rotation gesture while retaining the existing absolute Rotation numeric property for direct entry. Panel-triggered Rotation and Size use the same cancellation, regeneration, anchor, Maintain Connected, and Object Scale normalization behavior as their keyboard and overlay equivalents.

All pointer-driven Rotation and Size entry paths use one modifier contract:

- Shift reduces pointer sensitivity to one-tenth for continuous fine adjustment;
- Ctrl snaps Rotation to `rotation_snap_degrees` and Size to `0.1×` factor increments;
- Shift+Ctrl snaps Rotation to one-tenth of `rotation_snap_degrees` and Size to `0.01×` increments;
- typed numeric values remain exact and bypass pointer snapping.

Modifier changes during a gesture are evaluated from the unsnapped gesture baseline so toggling Shift or Ctrl does not accumulate rounding drift.

### Committed-profile fields

The committed-profile HUD shows:

- editable `Rotation`;
- editable `Uniform Scale`.

Both fields read `cpc_profile_placement_json` and apply changes through the canonical profile placement setter. Exact Rotation input is an absolute degree value. Exact Uniform Scale input is an absolute positive scale value matching the existing numeric panel field. Scrubbing begins from a fixed baseline, and cancellation restores that complete baseline.

If a legacy positive uniform Blender Object Scale is present when profile semantic editing begins, it is captured through the existing profile-resize migration logic and absorbed when an edit is accepted. Cancelling restores the original semantic state and raw Object Scale. Non-uniform or non-positive Object Scale is rejected with a clear message rather than guessed. The accepted result leaves Object Scale neutral.

### Presentation and synchronization

`viewport_overlay.py` becomes target-agnostic for semantic text fields while retaining the current restrained HUD, hit rectangles, anchor guides for parts, and lazy draw-handler lifecycle. Component-only endpoint guides are not drawn for committed profiles.

The semantic field adapter reads live authoritative values every draw/update. Therefore panel properties, placement wheel, G/R/S, viewport edits, Edit Active Profile, Recommit, and reload cannot drift into separate overlay state.

## Issue #6: Reconnect Touching Endpoints

### Candidate scope

The operator resolves candidates in this order:

1. all non-preview CPC parts in the active build or Edit Active Profile session;
2. otherwise, the currently selected non-preview CPC construction parts.

An active session is scanned as a whole so reconnection repairs a complete construction chain rather than only the visible selected pair. Parts outside the resolved scope are not mutated.

### Pure reconnection plan

A Blender-independent planner receives endpoint records sorted by construction sequence, object key, then endpoint index. Each record contains an object key, endpoint index, world-space coordinates, and current junction ID.

The planner groups endpoint records by Euclidean distance within `merge_tolerance`, using transitive clustering. A reconnectable cluster must contain at least two endpoints belonging to different objects. For each reconnectable cluster:

- keep the first existing non-empty junction ID in stable endpoint order;
- merge any additional existing IDs into that survivor;
- create one new junction ID only when the cluster has none;
- assign the surviving/new ID to every endpoint in the cluster.

Endpoints outside reconnectable clusters retain their current IDs. A cluster with one existing ID retains that ID unchanged. This preserves valid semantic relationships while repairing physically snapped chains.

### Blender application

The operator snapshots endpoint coordinates, computes the plan, and applies only junction metadata. An endpoint-to-endpoint reconnection supersedes any hosted attachment on the affected endpoint, matching existing `connect_endpoints` semantics. No matrix, curve point, handle, parameter, or placement value is written.

The operator reports the number of clusters, endpoints, newly created IDs, and merged IDs. No touching pairs produces an INFO report and returns `CANCELLED`, avoiding an empty undo mutation. The operation is explicit and never runs from depsgraph, placement, or proximity callbacks.

The Build Profile UI exposes `Reconnect Touching Endpoints` next to the existing Maintain Connected controls/utilities.

## Issue #7: validation and release gate

### Automated verification

Before each candidate package and before any completion claim:

- run the complete Python unit suite with bytecode generation disabled;
- parse/compile every shipped Python module;
- run whitespace/diff checks;
- verify deterministic endpoint-planner cases and semantic overlay gesture cases;
- verify Shift fine motion, Ctrl snapping, Shift+Ctrl fine snapping, and exact typed values for Rotation and Size;
- build the Blender extension archive;
- verify ZIP integrity and confirm exclusion of `.git`, `tests`, `__pycache__`, `.pyc`, and nested ZIP files.

New behavior follows test-driven development. Each behavioral test must be observed failing for the intended missing behavior before production code is added.

### Production Blender validation

The release candidate includes a 0.4.4 validation document covering CRN-4000 through CRN-4004 and the issue #7 matrix:

- Offset X/Y, Rotation, Flip X/Y, Uniform Scale, and combined transforms;
- placement-time versus post-placement equivalence;
- Blender Move/Rotate/Scale semantic routing;
- viewport Rotation and Size/Uniform Scale editing;
- component Object Scale normalization;
- Reconnect Touching Endpoints and Maintain Connected afterward;
- save/reload, Edit Active Profile, Recommit, and Sweep;
- recipe schema 11+, transform schema 1, PARAMETRIC/STATIC behavior, identity, normalization, packed restoration, bevel linkage, and lazy overlay handlers.

This workspace has neither Blender nor the CRN production files. The user will install the candidate ZIP, execute the matrix, and report results. Issue #7 and the release gate remain open until the user explicitly confirms the production set passes. Any reported failure receives a reproducing test where automation is possible, a fix, a new candidate, and focused revalidation.

## Expected code boundaries

- `viewport_semantics.py`: target/field adapters and authoritative semantic reads/writes.
- `viewport_overlay.py`: generic rendering and hit testing for component/profile semantic fields.
- `operators.py`: gesture lifecycle, reconnect operator, registration, and stable keymap behavior.
- `junctions.py` plus a small pure planning module if needed: endpoint metadata application and testable clustering.
- `ui.py`: viewport-edit wording, selected-part Rotation/Size gesture controls, and reconnect control.
- `tests/`: overlay semantic and reconnection regression coverage.
- release documentation listed above.

Unrelated refactoring is outside scope.
