# CPC 0.4.6 — Custom Bézier Integration Design

Date: 2026-10-07
Status: Development spike
Baseline: CPC 0.4.4 validated release

## Purpose

CPC's semantic component catalogue is efficient for dimension-driven architectural shapes, but some profile transitions are inherently freeform. 0.4.6 explores a mixed workflow where the user can construct a profile with ordinary CPC components, extend that chain with a native Blender Bézier section, then continue with CPC components.

The goal is not to turn CPC into another Bézier editor. Blender already provides mature control-point and handle editing. CPC should provide the bridge between that native editing and CPC's construction, connectivity, Commit/Recommit and Sweep workflows.

## Example workflow

```text
CPC Line
   ↓
CPC Ovolo
   ↓
Native Blender Bézier section
   ↓
CPC Cove / Arc / next component
```

A typical user workflow is:

1. build Line + Ovolo using the normal CPC Add + Snap workflow;
2. create a native Blender Bézier curve for the unusual transition;
3. snap its first Bézier point to the Ovolo exit;
4. shape it in Blender Edit Mode using native control points and handles;
5. adopt/commit that curve into the CPC construction;
6. preserve its editable Bézier data;
7. use its final point as the connection anchor for the next CPC component;
8. continue normal CPC construction and Commit/Sweep workflows.

## Representation

The custom section has:

- an entry anchor;
- native Blender Bézier spline data;
- an exit anchor;
- a CPC component placement/local transform;
- CPC connectivity metadata.

The first Bézier point is the entry anchor and local origin.

```text
entry/local origin
      ↓
      ●────●
            \
             ●────●
                  ↑
               exit anchor
```

All internal coordinates and handle positions should be stored or reconstructed relative to the component-local frame where practical.

The final Bézier point defines the exit anchor.

## Native Bézier data to preserve

For every Bézier point, preserve at minimum:

- control-point coordinate;
- left handle coordinate;
- right handle coordinate;
- left handle type;
- right handle type.

Other spline-level settings should be preserved wherever they materially affect the resulting native Blender curve.

The implementation must not approximate the section by sampling it into a dense STATIC polyline merely for CPC storage.

## Keep Components Together

When an upstream component moves its exit anchor from A to A', the custom section should follow without changing its local shape.

Conceptually:

```text
old_component_transform → new_component_transform
```

not:

```text
rewrite every local Bézier point to create a new shape
```

The visual effect is equivalent to applying the same delta/transform to all control points and handles, but the preferred internal model is to retain stable local geometry and update the custom section's placement transform.

The custom section's exit anchor therefore moves with it, and downstream CPC components continue to propagate from the new exit position.

## Rotate All / Move All

Assembly-level transforms must apply coherently to:

- semantic CPC components;
- the custom Bézier section;
- all native control points and handles through the section transform;
- downstream connected components.

Rotate All must not alter the local Bézier shape.

## Commit / Recommit

Commit must retain sufficient data to reconstruct the native Bézier section losslessly.

Recommit must allow the user to return to native Blender editing without losing:

- point count;
- control-point positions;
- handle positions;
- handle types;
- entry/exit anchor relationships.

Object identity rules for the committed profile should remain consistent with the validated 0.4.4 Recommit behaviour.

## Connection policy for the first implementation

Required:

- exact positional attachment at entry;
- exact positional attachment at exit;
- directed CPC connectivity through the section.

Deferred:

- automatic tangent alignment;
- automatic tangent inheritance from adjacent CPC parts;
- automatic stretching/deformation when both neighbouring anchors change;
- CPC-authored Bézier handle editing UI.

## First implementation spike

Implement the smallest end-to-end proof using an already-created Blender Bézier curve.

Acceptance cases:

1. Build CPC Line → Ovolo.
2. Create a Blender Bézier curve separately.
3. Attach/adopt its first point at the Ovolo endpoint.
4. Commit.
5. Re-edit/recommit and verify Bézier handles survive unchanged.
6. Resize or otherwise alter the upstream CPC component with Keep Components Together enabled.
7. Verify the custom section moves rigidly from its entry anchor.
8. Attach another CPC component to the custom section's exit anchor.
9. Verify propagation through the complete chain.
10. Verify Move All.
11. Verify Rotate All.
12. Verify Commit/Recommit object identity expectations.
13. Verify Sweep works with the resulting combined profile.

## Explicit non-goals for this spike

- no new S-curve or half-S-curve semantic component;
- no custom CPC Bézier solver;
- no automatic tangent-continuity system;
- no automatic deformation solver;
- no dedicated drawing mode until adoption of an existing Blender Bézier is proven.

## Historical note

The 0.4.5 edit-point direction is intentionally abandoned. It may be preserved separately as development history, but 0.4.6 starts from the validated 0.4.4 baseline.
