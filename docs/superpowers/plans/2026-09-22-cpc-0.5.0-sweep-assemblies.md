# CPC 0.5.0 Sweep Assemblies Implementation Plan

## Purpose

Implement the approved Sweep Assemblies design on top of the validated 0.4.4 baseline without weakening existing profile authority, transform semantics, User Profile safety, or single-profile Sweep behavior.

The implementation order deliberately establishes pure data contracts and non-destructive profile embedding before any UI or Blender scene generation.

## Protected baseline

The implementation must preserve:

- recipe schema 11+;
- transform schema 1;
- `.cpcprofile` format v1;
- PARAMETRIC / STATIC classification;
- committed-profile in-place Recommit;
- canonical complete-profile placement;
- semantic component Size with neutral Object Scale;
- explicit endpoint reconnection;
- User Profile Categories/Search/indexing;
- persistent User Profile path;
- existing single-profile Sweep behavior;
- 2D Caps / Fill Mode semantics;
- lazy viewport overlay handlers.

No task may write back to a User Profile preset unless the user invokes an explicitly named source-update operation.

## Task 2 — Reusable embedded profile payloads

**Files**
- Create: `profile_payloads.py`
- Modify: `user_profiles.py`
- Modify: `profile_presets.py` only if validation helpers need to be exposed
- Create: `tests/test_profile_payloads.py`

**Goal**

Extract the existing User Profile serialization semantics into reusable helpers so `.cpcprofile` and assembly members use the same geometry/recipe authority model.

**Required behavior**

A payload created from a complete profile must contain enough data to reconstruct that profile without the source preset file.

PARAMETRIC payload:
- normalized curve geometry;
- recipe schema;
- transform schema;
- frame policy;
- recipe records;
- profile type;
- authority-relevant fields.

STATIC payload:
- normalized visible geometry;
- profile type;
- no false editable recipe claim.

**Proposed interfaces**

```python
profile_payload_from_object(obj) -> dict
validate_profile_payload(payload) -> dict
instantiate_profile_payload(context, payload, name, collection) -> bpy.types.Object
profile_payload_authority_hash(payload) -> str
```

Refactor `save_profile_preset()` and `load_profile_preset()` to consume these helpers rather than maintaining two serializers.

**Critical safety tests**

- [ ] A payload round-trips a PARAMETRIC profile.
- [ ] A payload round-trips a STATIC profile.
- [ ] Instantiation does not depend on a preset path.
- [ ] Deleting the original `.cpcprofile` does not invalidate a previously embedded payload.
- [ ] Payload provenance is not treated as write authority.
- [ ] Existing User Profile tests continue to pass unchanged.

Commit:


## Task 3 — Assembly scene controller and authoring state

**Files**
- Create: `sweep_assemblies.py`
- Modify: `properties.py`
- Modify: `library.py` if a dedicated collection helper is needed
- Create: `tests/test_sweep_assembly_state.py`

**Goal**

Represent a scene assembly definition with stable identity while keeping the committed definition unchanged during an edit session.

**Scene model**

Use a CPC-owned Empty controller object or equivalent stable scene owner with:

- `cpc_sweep_assembly = True`
- `cpc_assembly_id`
- `cpc_assembly_json`

The JSON stores the committed Assembly Definition.

Scene settings gain:

- `active_sweep_assembly`
- `editing_assembly_id`
- `editing_assembly_member_id`

**Working-copy rule**

**Edit Assembly must not mutate `cpc_assembly_json` while editing.**

Instead, reconstruct member authoring objects from the committed definition into a dedicated temporary/edit collection.

Therefore:

```text
committed controller JSON
        ↓ Edit Assembly
temporary authoring member objects
        ↓ edit freely
Recommit Assembly
        ↓ serialize working copy
committed controller JSON replaced
```

Cancel simply discards authoring objects and leaves committed JSON untouched.

**Tests**

- [ ] Active assembly resolves by ID rather than name.
- [ ] Beginning edit leaves committed JSON byte-for-byte unchanged.
- [ ] Cancel discards working objects without changing committed JSON.
- [ ] Recommit serializes member order, payloads, and placements.
- [ ] Duplicate object names do not affect identity.

Commit:

```bash
git add sweep_assemblies.py properties.py library.py tests/test_sweep_assembly_state.py
git commit -m "Add Sweep Assembly scene authority"
```

**Input**

Two or more selected complete Curve profiles that are not CPC construction-part previews.

**Behavior**

6. Do not modify or delete source User Profile presets.

**Tests**

- [ ] Object Scale is not persisted as an alternate authority.
- [ ] Source preset ID/hash is copied only as provenance.
- [ ] Assembly remains valid if source provenance is blank.

## Task 10 — `.cpcassembly` save/load and source provenance actions

**Files**
- Create: `assembly_library.py`
- Modify: `assembly_presets.py`
- Modify: `operators.py`
- Modify: `ui.py`
- Create: `tests/test_assembly_library.py`
- Create: `tests/test_assembly_source_safety.py`

**Persistence**

For 0.5.0, `.cpcassembly` documents may share the configured CPC writable library root but use a separate scanner and selector. They must not be added to the User Profile category/index contract.

No thumbnails/categories are required for the first release.

**Operations**

- Save Assembly;
- Load Assembly;
- Delete Assembly;
- Save Member as New User Profile;
- Update Source User Profile…;
- Reload Member from Source….

**Safety contract**

`Save Member as New User Profile` is the normal/default export action.

`Update Source User Profile…` requires:

1. valid source preset identity;
2. current-source lookup;
3. source-difference check;
4. explicit confirmation;
5. re-fetch/revalidate before overwrite.

`Reload Member from Source…` also requires explicit confirmation because it discards the current embedded variant.

**Tests**

- [ ] Save/load round-trip preserves assembly/member IDs.
- [ ] PARAMETRIC/STATIC member payloads round-trip.
- [ ] Missing source file does not prevent assembly load.
- [ ] Recommit Member cannot overwrite source.
- [ ] Recommit Assembly cannot overwrite source.
- [ ] Refresh cannot overwrite source.
- [ ] Save as New creates a new preset ID/path.
- [ ] Update Source targets only the recorded/confirmed source.
- [ ] Reload from Source replaces only the selected member payload.
