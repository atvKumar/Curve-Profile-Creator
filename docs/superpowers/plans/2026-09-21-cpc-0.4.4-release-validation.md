# CPC 0.4.4 Release Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Audit issues #2 through #10, document the shipped 0.4.4 behavior, build a clean release candidate, complete the CRN-4000–CRN-4004 Blender gate, and hand off the verified branch for integration.

**Architecture:** Treat the existing unit suite, source parsing, archive inspection, and independent code review as the automated gate. Record the production matrix in a versioned validation document and require explicit user confirmation from Blender before changing its status to passed or closing GitHub issues. Package only committed source files, excluding tests and internal planning documents.

**Tech Stack:** Git, Python 3 `unittest`/`ast`, ZIP tooling, SHA-256, Blender 4.3+ manual validation, GitHub connector.

**Spec:** `docs/superpowers/specs/2026-09-21-cpc-0.4.4-release-closeout-design.md`

**Execution order:** Run after the semantic-controls and reconnect-endpoints plans are implemented, reviewed, and green.

## Global Constraints

- Issue #7 stays open until CRN-4000 through CRN-4004 pass in Blender.
- Keep recipe schema 11+, transform schema 1, `.cpcprofile` format v1, and manifest version 0.4.4.
- Preserve PARAMETRIC/STATIC behavior, Recommit object identity, Sweep bevel linkage, packed restoration, normalization, and lazy overlay handlers.
- Do not include `.git`, `tests`, `docs/superpowers`, `__pycache__`, `.pyc`, or nested ZIP files in the install archive.
- WebP thumbnail conversion is not part of 0.4.4.
- Do not close issues, merge, tag, or publish a GitHub Release before the specified gates.
- Any Blender failure returns to a reproducing test where possible, then a focused fix, review, rebuilt candidate, and revalidation.

## Review Focus

- Saved 0.4.3-era PARAMETRIC and STATIC presets lacking 0.4.4 placement state must still load without schema migration; Task 1 audits this against existing loaders and Task 4 tests it in Blender.
- Repeated Edit Active Profile/Recommit must keep the committed object identity and not double-apply placement; Task 1 verifies existing automated coverage and Task 4 records production evidence.
- Sweep paths must retain the bevel-object relationship while Caps controls only the path's supported fill behavior; Task 4 explicitly checks 2D and 3D paths.
- The final ZIP must not contain source tests or bytecode even after running tests immediately before packaging; Task 3 runs tests first and inspects every archive member afterward.
- Closing multiple milestone issues must never precede a failed or incomplete production row; Task 5 requires an all-pass validation document before any GitHub state mutation.

## File Structure

- Modify `README.md`: user-facing 0.4.4 summary and compatibility promises.
- Modify `ARCHITECTURE.md`: canonical placement, semantic component sizing, overlay routing, and explicit endpoint reconstruction.
- Modify `ROADMAP.md`: make transform/connectivity the 0.4.4 release and move WebP to later candidates.
- Modify `CHANGELOG.md`: complete 0.4.4 release notes.
- Create `VALIDATION_Curve_Profile_Creator_0.4.4.md`: candidate evidence and CRN production matrix.
- Modify code/tests only if the audit or Blender validation identifies a concrete gap; every such change follows a new red/green cycle.
- Create the candidate/final ZIP one directory above the repository; archives are artifacts, not tracked source.
